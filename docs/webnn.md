# WebNN для моделей ФИО

[Русский](webnn.md) · [English](webnn.en.md)

Браузерный адаптер запускает `person-default.bin` и `person-prose.bin` через WebNN либо JavaScript. Модель возвращает интервалы `PERSON` в координатах UTF-16. В примере эти интервалы заменяются маркером `[PERSON]`.

## Запуск примера

```sh
python3 -m http.server 47833 --bind 127.0.0.1
```

Откройте [127.0.0.1:47833/examples/WebNN/index.html](http://127.0.0.1:47833/examples/WebNN/index.html). Выберите модель и режим вычислений. Предпочитаемое устройство передаётся WebNN как `cpu`, `gpu` или `npu`. Доступность зависит от браузера, ОС и реализации операций.

Для WebNN требуются secure context, `navigator.ml.createContext`, `MLGraphBuilder` и поддержка float32 `matmul`. HTTPS и loopback подходят для запуска примера. В браузерах с экспериментальной реализацией может потребоваться включение WebNN. Для изолированной проверки Chromium использовался флаг `--enable-features=WebMachineLearningNeuralNetwork`.

## JavaScript API

```javascript
import { createPersonDetector } from "./adapters/web/person-detector.mjs";

const response = await fetch("./models/person-prose.bin");
if (!response.ok) throw new Error("model-unavailable");
const detector = await createPersonDetector(await response.arrayBuffer(), {
  backend: "auto",
  deviceType: "cpu"
});
try {
  const spans = await detector.find("Контакт: Алина Зорничева");
  console.log(spans);
  console.log(detector.status);
} finally {
  await detector.dispose();
}
```

| `backend` | Поведение |
| --- | --- |
| `auto` | Пробует WebNN, затем использует JavaScript при ошибке и записывает причину |
| `webnn` | Требует WebNN, возвращает ошибку при создании или выполнении графа |
| `javascript` | Использует переносимый локальный scorer |

`status.activeBackend` показывает фактический API. `requestedDevice` отражает предпочтение устройства, переданное браузеру. `fallbackReason` показывает отсутствие API, ошибку инициализации, несовпадение численных оценок или сбой вычисления.

## Вычисления

Граф содержит матричное умножение float32. Для каждого токена строятся три варианта признаков по возможной предыдущей BIO-метке. Матрица хранит количество попаданий признаков в бакеты. Постоянная матрица содержит коэффициенты модели. Последовательный выбор метки выполняется в JavaScript, включая переход через границу батча.

По умолчанию батч содержит 16 токенов. Можно задать `batchTokens` от 1 до 32. При 8192 бакетах входная матрица батча по умолчанию занимает 1,5 МиБ. Тензоры переиспользуются, вызовы `find` выполняются по очереди. `dispose` дожидается их завершения и освобождает граф и контекст.

Коэффициенты int16 преобразуются в float32. Сумма двенадцати коэффициентов укладывается в диапазон точных целых float32. Перед использованием граф проходит проверку на контрольной матрице. При изменённых численных результатах режим `auto` выбирает JavaScript. Эта проверка не заменяет сравнение на целевых данных и устройстве.

Токенизация, Unicode-регистр, хэширование признаков и BIO-декодировка сверены с .NET. Ограничения совпадают с `MicroPersonModel` — 256 КиБ UTF-8 на вход, 8192 токена и 256 символов UTF-16 на токен. Словарь фамилий для инференса не нужен.

## Граница интеграции

Этот адаптер реализует модель ФИО. Контекстные правила, email, телефоны, секреты, реквизиты и псевдонимизация входят в основной конвейер ag-privacy. Интервалы модели могут содержать пропуски и ложные срабатывания.

Пример загружает статические модули и веса с того же сервера. Введённый текст остаётся в браузере. В автоматической проверке фиксировались только GET-запросы за ресурсами.

## Проверка

Для тестов нужен Node.js 20 или новее.

```sh
node --test tests/javascript/*.test.mjs
dotnet run --project test-support/AgPrivacy.WebFixtures -c Release -- \
  tests/javascript/fixtures/person-model-parity.json
```

JavaScript и WebNN проверяются по сохранённым результатам .NET для 400 синтетических примеров. Отдельные тесты с программной имитацией API проверяют потерю устройства, освобождение ресурсов, очередность вызовов и причины fallback.

На macOS arm64 в отдельном Chromium без экспериментального флага проверен JavaScript fallback. С включённым флагом обе модели прошли все 400 сравнений через настоящий WebNN с предпочтением CPU. Это проверка WebNN API на данном окружении. Скорость и доступность GPU/NPU определяются конкретной системой.

Официальные требования и API описаны в [спецификации WebNN](https://www.w3.org/TR/webnn/).
