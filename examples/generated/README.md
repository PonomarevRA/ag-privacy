# Синтетический пример маскирования

Все значения в этих файлах придуманы для демонстрации. Email используют зарезервированный домен `example.test`, адрес `192.0.2.42` относится к диапазону примеров. Телефоны, ФИО и номера документов используются как синтетические значения.

| Формат | До | После |
| --- | --- | --- |
| JSON, режим просмотра strict | [Исходный JSON](json_before.json) | [Строгие маркеры](json_strict_display.json) |
| JSON, soft-part | [Исходный JSON](json_before.json) | [Частичная маска](json_soft_part.json) |
| JSON-логи | [Исходные записи](logs_before.ndjson) | [Подстановка букв и цифр](logs_after.ndjson) |
| CSV с разделителем `;` | [Исходная таблица](table_before.csv) | [Результат](table_after.csv) |
| XML | [Исходный документ](document_before.xml) | [Результат](document_after.xml) |

Обычные JSON-ключи `email` и `tags` сохранены, ключи с фактическими email и телефоном заменены. В произвольных полях обнаруживаются email, телефон и номер договора. В логах сохраняются `trace.id`, служебный логин и дата подписания. Дата рождения скрывается. CSV-заголовок и XML-тег `fullName` определяют правило для вымышленного значения `Fixture Person`.

В этом прогоне `approved` ошибочно замаскировано как `PERSON` внутри сообщения, CSV и XML. Это пример ложного срабатывания текущего детектора. В режимах просмотра JSON поле `status` с тем же значением сохраняется. Результаты требуют проверки на данных конкретной интеграции.

Количество замен по правилам находится в [summary.json](summary.json). Новый запуск `examples/Quickstart` использует новый случайный ключ, поэтому сами подстановки будут другими.
